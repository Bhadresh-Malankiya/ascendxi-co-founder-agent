# Extending the lean company

Prefer an existing owner and a new capability profile in `company/catalog.ts` before adding a runtime agent. `company/team.ts` maps every historical capability to one accountable owner; `agents/team.ts` builds the five team agents, and the main co-founder plus monitor are registered in `src/mastra/index.ts`. More projects must not create more employees automatically.

A new owner requires evidence of a missing responsibility/workload and founder approval. Keep quality independent; quality-owned work is reviewed by the co-founder. Add exact integration grants only to the actual current owner after approval, through connections.ts/policy.ts. Never merge retired grants or give growth/support the engineering workspace. Update routing, pause aliases, model policy and tests together. New plan/goal execution must pass centralized revision/dependency gates, including direct workflow entry; UI-only gates are insufficient.

The legacy department/orchestrator/role modules remain source references, not part of the live registration. Historical tasks and preferences remain in storage. Do not delete them or assume their permissions migrated. See [plans, decisions and recovery](plans-and-blockers.md) and AGENTS.md for required checks and artifact-only workflow boundaries.
