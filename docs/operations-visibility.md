# Reading the live company desk

The main screen reports actual execution rather than inferring activity from a worker heartbeat. An online worker can legitimately be idle. Routine polling does not spend model tokens or count as AI work.

- **Executing**: current model runs or claimed assignments, only with a fresh worker heartbeat.
- **Ready to start**: eligible queued assignments whose owner is not paused. A queued dependency is not ready work.
- **Waiting / blocked**: unresolved prerequisites, blocked assignments and pending reviews.
- **Completed documents**: accepted internal artifacts. This does not establish product implementation, deployment, sales or launch readiness.

The primary blocked task is chosen by priority. Its resolution control opens the exact diagnostic, recovery and evidence controls. A task-bound proposed access/budget/service/deployment decision opens the existing request instead of creating a duplicate. Recording consent does not configure or verify a provider connection.

The focus view names each milestone's actual prerequisites from its own plan. Matching milestone keys in another plan do not satisfy a dependency. Completed results open the retained task report and review evidence.

The existing authenticated server-sent event stream updates counts, worker freshness, task state and real model output. Active output is shown only while a recorded model run is active; completed work and missing inputs remain visible when idle. Open dialogs and draft forms are preserved across snapshots.

The current company-task workflow is an internal planning and independent review workflow. Product repository edits, product deployment and new provider permissions need separately implemented, verified execution paths. Making the local worker continuous does not create these capabilities.

## Verification

Pure tests cover transitive blockers, existing decision links, cross-plan key collisions, paused owners, stale running records and missing worker configuration. Browser checks must distinguish real completed artifacts and live heartbeat updates from actual model activity; do not create dummy assignments simply to animate the desk.

Warm project/task initialization checks the catalog before issuing column or index migrations. Existing schemas are not locked exclusively just to repeat an already-applied alteration. The dedicated regression test holds real project/task read locks while fresh store instances initialize, with a server-side statement deadline.

Each company assignment and independent review receives a current server policy snapshot. Historical four-job statements in retained plans or reports are not active limits when the server policy is zero. Retained reports remain dated evidence and are never silently rewritten.
